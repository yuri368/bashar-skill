# Bashar Skill

一个面向 Codex / AI Agent 的 Bashar（巴夏）原文资料检索与回答辅助 Skill。

本项目用于整理、检索和引用 Bashar 相关原文资料，帮助 AI 在回答巴夏相关问题时，尽量回到可追溯的原始文本，而不是生成泛化、鸡汤化或脱离语境的灵性解释。

> 当前项目仍处于早期版本，资料结构、索引质量、主题整理和回答规则都还在持续完善中。

---

## 项目定位

`bashar-skill` 目前主要的用途为本人个人使用，随带发布到GitHub上，大部分内容为Codex生成，并不保证质量如何。

它是一个围绕 Bashar 原文资料建立的本地知识 Skill，目标是让 AI 在处理以下问题时，先检索资料库，再基于原文作答

本项目的核心原则是：

> 先找原文，再组织回答。

---

## Bashar 简介

Bashar（巴夏）通常被介绍为通过传讯者 Darryl Anka 进行表达的 Essassani 文明意识。

相关资料中，Bashar 的讯息常围绕以下主题展开：

* 兴奋与行动
* 信念与定义
* 恐惧与限制性信念
* 同步性
* 显化
* 臣服与允许
* 平行实相
* 个人责任
* 星际文明与意识进化

本项目不负责证明或反驳 Bashar 体系本身，而是专注于对已有文本资料的整理、检索和引用。

---

## 为什么需要这个 Skill？

避免出现几个问题：

1. **过度总结**：把复杂的原文对话压缩成一句口号。
2. **语境丢失**：只保留结论，不保留问题、追问和定义过程。
3. **心理学化或鸡汤化**：把 Bashar 的表达改写成普通自我成长建议。

`bashar-skill` 的目标不是让 AI “装作懂 Bashar”，而是让 AI 先回到 Bashar 资料库，再基于可追溯文本进行回答。

---

## 核心功能

### 1. 原文优先检索

当用户提出类似问题时：

* “巴夏原文怎么说？”
* “资料库里有没有关于恐惧的说法？”
* “这句话和巴夏原文冲突吗？”
* “按 Bashar 的说法回答这个问题。”

Skill 会优先检索 `sources/` 中的原文资料，并尽量在回答中保留来源路径、上下文和概念边界。

---

### 2. Bashar-only 资料筛选

当前公开仓库由本地完整资料库导出，并筛选为 Bashar-only 版本。

---

### 3. 核心词汇定义库

`巴夏词汇定义.md` 用来记录 Bashar 原文中的高频概念定义。

目前重点整理的词汇包括：

* 定义
* 核心信念
* 兴奋
* 恐惧
* 职业 / 目标
* 臣服
* 祈祷
* 责任

这个文件的原则是：

* 不做自由发挥式总结
* 不把概念改写成泛灵性话术
* 尽量保留短原文锚点
* 每条定义尽可能附带来源路径

---

### 4. 人工主题索引

`巴夏主题索引.md` 是人工维护的高价值入口文件。

它用于把常见主题和最值得优先检索的原文资料连接起来，例如：

* 跟随最高兴奋
* 恐惧与负面信念
* 限制性信念
* 同步性
* 显化
* 行动与祈祷
* 平行实相

主题索引采用固定格式：

```markdown
- `[1][-]` `sources/...` —— 用途说明
```

标记含义：

| 标记    | 含义                |
| ----- | ----------------- |
| `[1]` | 最高优先级入口           |
| `[2]` | 次优先级入口            |
| `[3]` | 扩展或对照入口           |
| `[+]` | 已锁定，默认不替换、不删除、不降级 |
| `[-]` | 可正常迭代             |

每个主题默认控制在 3 篇以内，最多不超过 5 篇，避免索引无限膨胀。

---

### 5. 预计算全文索引

`sources/_meta/search_index.jsonl` 是预计算全文检索索引。

`scripts/search_sources.py` 会优先读取该索引。如果索引不存在，会自动回退到：

```text
sources/_meta/articles.jsonl
```

这样即使没有提前构建索引，基础检索功能仍然可以运行。

---

### 6. 可持续迭代机制

这个 Skill 被设计为一个持续迭代的资料系统。

当用户指出以下问题时，应该同步修改对应文件：

* “这个回答不像 Bashar。”
* “这和原文冲突。”
* “以后不要这样说。”
* “这个表达可以保留。”
* “把这个加入 Skill。”
* “继续优化这个 Skill。”

实质性修改后，应更新：

```text
迭代历史.md
```

## Skill 回答原则

更完整的行为规则见 `SKILL.md`。

简化原则如下：

1. 能查原文，就先查原文。
2. 回答时尽量保留来源路径和上下文。
3. 不把 Bashar 内容过度心理学化、管理学化或鸡汤化。
4. 遇到关键词，优先查 `巴夏词汇定义.md`。
5. 遇到主题问题，优先查 `巴夏主题索引.md`。
6. 回答风格尽量保留 Bashar 式的短句、定义、追问和行动落地。
7. 如果 Skill 规则与原文冲突，原文优先，并反向校准 Skill。

## 维护规则

建议按以下方式维护：

1. 修改 `SKILL.md` 时，优先以原文为准。
2. 新增词汇定义时，写入 `巴夏词汇定义.md`，并保留来源路径。
3. 新增主题入口时，写入 `巴夏主题索引.md`。
4. 修改资料库后，重建 `sources/_meta/search_index.jsonl`。
5. 每次实质性修改后，更新 `迭代历史.md`。
6. 不确定的总结不要写成定论，优先标记为待校准。
